# Инструмент визуализации графа зависимостей пакетов Alpine Linux

## Описание

Консольное приложение с окном на tkinter, которое получает информацию о зависимостях пакета из репозитория Alpine Linux (формат apk), строит граф зависимостей с учётом транзитивности и визуализирует его. Приложение написано на Python и использует только стандартную библиотеку. Менеджеры пакетов и сторонние библиотеки для получения зависимостей не применяются: индекс репозитория скачивается, распаковывается и разбирается самостоятельно.

## Возможности

Приложение извлекает прямые зависимости заданного пакета из файла APKINDEX репозитория. Оно строит полный граф зависимостей обходом в глубину без рекурсии, учитывает максимальную глубину анализа и исключает пакеты, в имени которых есть заданная подстрока. Циклические зависимости обрабатываются корректно, обход всегда завершается. Приложение умеет выводить порядок загрузки зависимостей, ASCII-дерево, описание графа на языке Graphviz и сохранять изображение графа в формате PNG. Есть тестовый режим, в котором вместо реального репозитория используется файл с описанием графа, где пакеты называются заглавными латинскими буквами.

## Требования

Нужен Python 3 с модулем tkinter. Для сохранения PNG нужна утилита Graphviz (команда dot должна быть доступна в PATH). Graphviz используется только для рисования и не участвует в получении данных о зависимостях. Если Graphviz не установлен, приложение всё равно сохранит текстовое описание графа в файл с расширением dot рядом с изображением. На Windows Graphviz можно установить командой winget install Graphviz.Graphviz или с сайта graphviz.org, указав добавление в PATH.

## Запуск

Приложение можно запустить двумя способами. Первый способ: передать опции при запуске из терминала, например python src/main.py --package nginx --repo https://dl-cdn.alpinelinux.org/alpine/v3.20/main/x86_64. Второй способ: запустить python src/main.py без аргументов, после чего в окне приложения после приглашения ввести опции, например --package A --repo ../tests/test1.txt --test-mode. В окне приложения нельзя вводить команду python, там вводятся только опции. Команда help выводит список опций, команда exit закрывает программу.

## Опции командной строки

Опция --package задаёт имя анализируемого пакета, она обязательна. Опция --repo задаёт URL репозитория или путь к файлу тестового репозитория. URL должен указывать на каталог с файлом APKINDEX.tar.gz, например https://dl-cdn.alpinelinux.org/alpine/v3.20/main/x86_64. Опция --test-mode включает режим тестового репозитория, при этом в --repo указывается путь к файлу. Опция --output задаёт имя файла с изображением графа, по умолчанию graph.png. Опция --ascii-tree включает вывод зависимостей в виде ASCII-дерева. Опция --max-depth задаёт максимальную глубину анализа, это неотрицательное целое число, по умолчанию 3. Опция --filter задаёт подстроку: пакеты, в имени которых она встречается, не учитываются при анализе. Опция --load-order включает вывод порядка загрузки зависимостей.

## Обработка ошибок

Приложение сообщает об ошибках понятным текстом и не завершается аварийно. Обрабатываются отсутствие обязательной опции --package, неизвестные опции и лишние аргументы, нецелое или отрицательное значение --max-depth, пустой или некорректный --repo, недоступный URL и HTTP-ошибки, повреждённый архив APKINDEX, отсутствие файла тестового репозитория, неверный формат строк в тестовом файле, отсутствие пакета в репозитории, а также ситуация, когда сам анализируемый пакет исключён фильтром.

## Как устроено получение данных

Репозиторий Alpine содержит архив APKINDEX.tar.gz, внутри которого лежит текстовый файл APKINDEX. Приложение скачивает архив средствами urllib, распаковывает его модулями gzip и tarfile и разбирает текст. Записи о пакетах разделены пустой строкой, каждая строка имеет вид буква, двоеточие и значение. Поле P содержит имя пакета, V версию, D список зависимостей через пробел, p список виртуальных имён, которые предоставляет пакет.

Токены зависимостей приводятся к именам пакетов. Ограничения версий, такие как знаки больше, меньше, равно и тильда, отбрасываются. Токены с префиксами so, cmd и pc сопоставляются с реальными пакетами через поле p. Конфликты, начинающиеся с восклицательного знака, пропускаются.

## Построение графа

Граф строится итеративным обходом в глубину с явным стеком. Корень имеет глубину ноль, его прямые зависимости глубину один. Вершины на предельной глубине попадают в граф, но не раскрываются и помечаются как не раскрытые. Для каждой вершины запоминается минимальная глубина, на которой она встречена, и если найден более короткий путь, вершина раскрывается повторно, чтобы результат не зависел от порядка обхода. Для обнаружения циклов хранится множество вершин текущего пути, ребро в вершину из этого множества считается обратным и фиксируется как цикл, а повторного захода в вершину не происходит.

## Тестовый режим

В тестовом режиме репозиторий описывается текстовым файлом, в котором каждая строка имеет вид имя пакета, двоеточие и список его зависимостей через пробел или запятую. Имена состоят только из заглавных латинских букв. Пустые строки и комментарии после символа решётки игнорируются. Пакет, который встречается только в списке зависимостей, считается пакетом без зависимостей. Примеры файлов лежат в каталоге tests. В test1 описан ромб без циклов, в test2 цикл через корень, в test3 петля и цикл не через корень, в test4 случай повторного раскрытия вершины при более коротком пути, в test5 более глубокий граф с разветвлением.

Пример запуска: python src/main.py --package A --repo tests/test1.txt --test-mode --ascii-tree. Путь к файлу считается от текущей папки, из которой запущена программа. Если программа запускается из каталога src, путь будет ../tests/test1.txt. В окне приложения для путей нужно использовать прямые слеши, а пути с пробелами брать в кавычки.

## Порядок загрузки

Опция --load-order выводит порядок, в котором нужно загружать пакеты, чтобы каждый пакет шёл после всех своих зависимостей. Порядок вычисляется итеративным обходом в глубину с выводом вершины после обработки всех её зависимостей. В циклических зависимостях строгий порядок невозможен, поэтому обратное ребро пропускается, а сами циклы выводятся отдельно. Вершины, не раскрытые из-за предела глубины, считаются листьями.

Для сравнения с реальным менеджером пакетов можно выполнить в Docker команду docker run --rm alpine:3.20 sh -c "apk add --simulate nginx", которая печатает порядок установки без самой установки, и сравнить её вывод с результатом программы при большой глубине анализа. Расхождения ожидаются по следующим причинам. В образе Alpine уже установлены базовые пакеты, и apk их не показывает, а программа включает. Менеджер apk учитывает ограничения версий, выбор провайдера виртуальных имён, правила install_if и конфликты, а программа берёт первого найденного провайдера и отбрасывает версии. Взаимно независимые пакеты могут идти в разном порядке, и оба порядка при этом корректны. Пакеты внутри циклов упорядочиваются по-разному. Опции --max-depth и --filter обрезают граф, а apk всегда ставит полное замыкание зависимостей. Общим для обоих результатов должно оставаться главное свойство: каждый пакет стоит после своих зависимостей.

## Визуализация

Граф описывается на языке Graphviz. Корневой пакет закрашивается, не раскрытые из-за предела глубины вершины рисуются пунктиром, рёбра, замыкающие циклы, выделяются красным цветом. Описание сохраняется в файл с расширением dot рядом с изображением, а PNG строится утилитой dot. Имя файла изображения задаётся опцией --output. Если указана опция --ascii-tree, зависимости дополнительно выводятся в виде дерева в окне приложения, повторяющиеся и циклические вершины в дереве помечаются.

Примеры визуализации лежат в каталоге docs. Для тестового репозитория используются запуски вида --package A --repo ../tests/test1.txt --test-mode --ascii-tree --output ../docs/test1_A.png, для цикла --package A --repo ../tests/test2.txt --test-mode --max-depth 5 --ascii-tree --output ../docs/test2_A.png, для другого корня --package D --repo ../tests/test5.txt --test-mode --ascii-tree --output ../docs/test5_D.png. Для реального репозитория можно выполнить --package nginx --repo https://dl-cdn.alpinelinux.org/alpine/v3.20/main/x86_64 --max-depth 3 --output ../docs/nginx.png.

## Сравнение со штатным инструментом

В менеджере apk есть собственная команда построения графа apk dot, которая выводит граф в формате Graphviz. Её можно выполнить в Docker командой docker run --rm alpine:3.20 sh -c "apk update >/dev/null && apk dot nginx" и построить изображение утилитой dot. Структуру графов нужно сравнивать по набору рёбер между пакетами, положение узлов на картинке значения не имеет.

Возможные расхождения объясняются следующим. Штатный инструмент показывает виртуальные зависимости с префиксами so, cmd и pc как отдельные узлы, а программа заменяет их реальными пакетами, поэтому её граф компактнее. Штатный инструмент подписывает узлы вместе с версиями, а программа использует только имена. Штатный решатель учитывает ограничения версий и выбор провайдеров, а программа берёт первого найденного. Программа ограничена параметрами --max-depth и --filter, а штатный инструмент показывает полное замыкание. Штатный инструмент знает об уже установленных в системе пакетах, а программа строит граф только по индексу репозитория. Конфликты программа пропускает, а штатный инструмент может показывать их отдельно. Стили, цвета и направление графа у инструментов различаются, но на структуру это не влияет.

## Демонстрация возможностей

Все примеры ниже используют тестовые файлы из каталога tests. Путь к файлу считается от папки, из которой запущена программа. Если программа запускается из корня проекта (Ку практика 2), путь пишется как tests/test1.txt. Если рабочей папкой является src, как это часто бывает при запуске из PyCharm, путь пишется как ../tests/test1.txt. Ниже используется вариант из каталога src, при запуске из корня уберите префикс две точки и слеш. Опции вводятся в окне приложения после приглашения либо передаются в командной строке после python src/main.py. Для краткости в выводах опущены блок с параметрами в начале и текст описания Graphviz в конце. Выводы получены разбором алгоритма по тестовым файлам, поэтому при проверке сравните их со своим запуском.

### Содержимое тестовых файлов

test1 описывает ромб без циклов. Строки файла: A: B C, затем B: D, затем C: D E, затем D: и E: без зависимостей.

test2 описывает цикл через корень. Строки: A: B, B: C, C: A D, D: без зависимостей.

test3 описывает петлю и цикл не через корень. Строки: A: A B, B: C, C: B.

test4 описывает случай, когда к вершине сначала находится длинный путь, а потом короткий. Строки: A: C B, C: B, B: D, D: E, E: без зависимостей.

test5 описывает более глубокий граф с общей зависимостью. Строки: A: B C, B: D, C: D, D: E F, E: без зависимостей, F: E.

### Случай 1. Граф без циклов и ASCII-дерево

Запуск: --package A --repo ../tests/test1.txt --test-mode --ascii-tree

```
Граф зависимостей пакета A (макс. глубина: 3, фильтр: нет):
  A -> B, C
  B -> D
  D -> (нет зависимостей)
  C -> D, E
  E -> (нет зависимостей)
Всего вершин: 5
Циклических зависимостей не найдено.

ASCII-дерево:
A
├── B
│   └── D
└── C
    ├── D
    └── E
```

Общая зависимость D присутствует в графе один раз, а в дереве повторяется под каждым из родителей.

### Случай 2. Ограничение глубины

Запуск: --package A --repo ../tests/test1.txt --test-mode --max-depth 1

```
  A -> B, C
  B -> … (не раскрыт: предел глубины)
  C -> … (не раскрыт: предел глубины)
Всего вершин: 3
```

При глубине один получаются только прямые зависимости, как на втором этапе. Значение ноль даёт граф из одного корня.

### Случай 3. Фильтр по подстроке

Запуск: --package A --repo ../tests/test1.txt --test-mode --filter D

```
  A -> B, C
  B -> (нет зависимостей)
  C -> E
  E -> (нет зависимостей)
Всего вершин: 4
```

Пакет D исключён из графа вместе со всем, что достижимо только через него.

### Случай 4. Цикл через корень

Запуск: --package A --repo ../tests/test2.txt --test-mode --max-depth 5 --ascii-tree

```
  A -> B
  B -> C
  C -> A, D
  D -> (нет зависимостей)
Всего вершин: 4
Циклические зависимости:
  A -> B -> C -> A

ASCII-дерево:
A
└── B
    └── C
        ├── A (цикл)
        └── D
```

Обход завершается, цикл найден и выведен отдельно, в дереве вершина помечена как цикл, а на изображении ребро C в A красное.

### Случай 5. Глубина обрывает цикл

Запуск: --package A --repo ../tests/test2.txt --test-mode --max-depth 2

```
  A -> B
  B -> C
  C -> … (не раскрыт: предел глубины)
Всего вершин: 3
Циклических зависимостей не найдено.
```

Цикл не обнаружен, потому что ребро C в A лежит за пределом заданной глубины.

### Случай 6. Петля и цикл не через корень

Запуск: --package A --repo ../tests/test3.txt --test-mode --max-depth 5

```
  A -> A, B
  B -> C
  C -> B
Всего вершин: 3
Циклические зависимости:
  A -> A
  B -> C -> B
```

### Случай 7. Повторное раскрытие вершины

Запуск: --package A --repo ../tests/test4.txt --test-mode --max-depth 3

```
  A -> C, B
  C -> B
  B -> D
  D -> E
  E -> … (не раскрыт: предел глубины)
Всего вершин: 5
```

Сначала обход идёт по пути A, C, B, D и упирается в предел глубины на вершине D. Затем находится более короткий путь A, B, и вершины B и D раскрываются заново, поэтому в графе есть зависимость D в E. Результат не зависит от порядка записи зависимостей.

### Случай 8. Порядок загрузки

Запуск: --package A --repo ../tests/test5.txt --test-mode --max-depth 5 --load-order

```
Порядок загрузки (зависимости раньше зависимых):
  1. E
  2. F
  3. D
  4. B
  5. C
  6. A
```

Каждый пакет стоит после всех своих зависимостей. Для ромба из test1 с опцией --load-order порядок будет D, B, E, C, A. Для цикла из test2 при глубине пять порядок будет D, C, B, A, а сам цикл выводится отдельным блоком.

### Случай 9. Другой корневой пакет и сохранение изображения

Запуск: --package D --repo ../tests/test5.txt --test-mode --ascii-tree --output ../docs/test5_D.png

```
  D -> E, F
  E -> (нет зависимостей)
  F -> E
Всего вершин: 3

ASCII-дерево:
D
├── E
└── F
    └── E
```

В каталоге docs появятся файлы test5_D.png и test5_D.dot. Если Graphviz не установлен, будет создан только файл dot, а программа сообщит об этом. Аналогично можно сохранить изображения для других пакетов, например test1_A.png и test2_A.png.

### Случай 10. Обработка ошибок

Пакет отсутствует в репозитории. Запуск: --package Z --repo ../tests/test1.txt --test-mode. Результат: Ошибка: пакет 'Z' не найден в тестовом репозитории.

Корневой пакет исключён фильтром. Запуск: --package A --repo ../tests/test1.txt --test-mode --filter A. Результат: Ошибка: пакет 'A' исключён фильтром 'A'.

Отрицательная глубина. Запуск: --package A --max-depth -2. Результат: сообщение о том, что глубина не может быть отрицательной.

Не указан обязательный параметр. Запуск: --repo ../tests/test1.txt. Результат: сообщение о том, что требуется аргумент --package.

Неверный путь к файлу. Запуск: --package A --repo tests/test1.txt --test-mode из каталога src. Результат: Ошибка: не удалось открыть файл, потому что файл нужно искать по пути ../tests/test1.txt.

Некорректное имя в тестовом файле, например строка a: b, приводит к ошибке с номером строки и пояснением, что имена должны состоять из заглавных латинских букв.

### Случай 11. Реальный репозиторий Alpine

Запуск: --package nginx --repo https://dl-cdn.alpinelinux.org/alpine/v3.20/main/x86_64 --max-depth 3 --ascii-tree --output ../docs/nginx.png

Приложение скачивает APKINDEX.tar.gz, строит граф зависимостей пакета nginx на глубину три и сохраняет изображение. Содержимое графа зависит от выбранной ветки Alpine, поэтому здесь оно не приводится. Для других примеров можно взять пакеты busybox и curl, меняя только значение --package.

## Структура проекта и расположение тестовых файлов

Проект лежит в папке Ку практика 2 на рабочем столе. В её корне находятся каталог src, каталог tests, служебные файлы .gitignore и .gitattributes, а также служебные каталоги .idea и .venv, которые в репозиторий не входят. В каталоге src лежит основной файл main.py. В каталоге tests лежат файлы тестовых репозиториев test1, test2, test3, test4 и test5. Проводник Windows может скрывать расширение, поэтому файл на самом деле называется test1.txt и так далее, в командах расширение нужно указывать. Каталог docs создаётся программой автоматически при сохранении изображений в него. Файл README.md лежит в корне проекта рядом с каталогами src и tests.

## Ограничения

Приложение разбирает только файл APKINDEX одного репозитория, поэтому зависимости, находящиеся в других репозиториях, например в community при анализе main, остаются вершинами без раскрытия. Скачивание индекса выполняется в основном потоке, и на время загрузки окно не отвечает. Версионные ограничения зависимостей не проверяются.

## История разработки

Работа выполнена по этапам. На первом этапе создан прототип с настройкой через командную строку и обработкой ошибок. На втором этапе реализован сбор прямых зависимостей из APKINDEX. На третьем этапе добавлены построение графа обходом в глубину без рекурсии, ограничение глубины, фильтр, обработка циклов и тестовый режим. На четвёртом этапе добавлен вывод порядка загрузки. На пятом этапе добавлены описание графа на языке Graphviz, сохранение PNG и ASCII-дерево. Каждый этап сохранён в репозитории отдельным коммитом в стиле Conventional Commits.
